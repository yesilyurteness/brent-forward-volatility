# Outputs Data Dictionary

Every file in this directory is generated by a script in [`../scripts/`](../scripts/) and
is committed so that the results can be audited without rerunning the pipeline. Nothing
here is edited by hand.

## A note on language

The documentation and all code comments in this repository are in English. Two things are
deliberately **not** translated:

- **The column names of the generated CSV files** (for example `fark_pct`,
  `isaret_kazanan`, `kareli_hata_payi_pct`).
- **The console output of the scripts**, which is why the `*_log.txt` files in this
  directory are in Turkish, as are the text fields inside some JSON reports.

These are kept as they are because the committed result files were produced by runs that
used exactly these names and messages. Renaming the columns would require regenerating
every output file, which would break the correspondence between the committed results and
the runs that produced them. This dictionary translates every non-English name instead.

Categorical values are also in Turkish and are listed with their meanings in the
[Categorical values](#categorical-values) section.

The files added in v1.1.0 (Stages 11-14 below) were generated with English column names
from the start; their console output is still in Turkish.

## File naming conventions

Several files come in variants that share a schema. Rather than repeating the tables, the
suffixes are defined once here.

| Suffix | Meaning |
| --- | --- |
| `_all` | Every horizon in one file |
| `_h5`, `_h22`, `_h66`, `_h126` | A per-horizon slice of the corresponding `_all` file, same columns: `wf_metrics_h5.csv`, `wf_metrics_h22.csv`, `wf_metrics_h66.csv`, `wf_metrics_h126.csv`, `wf_predictions_h5.csv`, `wf_predictions_h22.csv`, `wf_predictions_h66.csv`, `wf_predictions_h126.csv`, plus `wf_summary_h5.json` |
| `_aligned` | Every model restricted to XGBoost's warm-up start row, so all models see the same rows. Applies to the `bench_*` family: `bench_aggregate_all_aligned.csv`, `bench_folds_all_aligned.csv`, `bench_metrics_all_aligned.csv`, `bench_model_comparison_all_aligned.csv`, `bench_predictions_all_aligned.csv`, `bench_summary_all_aligned.json` |
| `_conv` | From the BiLSTM `--convergence-mode` robustness check. Applies to `bilstm_aggregate_all_conv.csv`, `bilstm_folds_all_conv.csv`, `bilstm_metrics_all_conv.csv`, `bilstm_predictions_all_conv.csv`, `bilstm_summary_all_conv.json`, `all_models_comparison_conv.csv` |
| `_rawsmearing` | The Optuna run **before** smearing shrinkage, kept as a methodological example for the paper's appendix |
| `*_run_log.txt` | Verbatim console transcript of that stage, in Turkish |

## Shared columns

These appear across many files and are not repeated in the per-file tables below.

| Column | Meaning |
| --- | --- |
| `horizon` | Forecast horizon h, in trading days (5, 22, 66, 126) |
| `fold` | Walk-forward fold number (1-15) |
| `test_year` | The year being forecast in that fold (2012-2026) |
| `include_in_main` | Whether the fold enters the main metric average. False only for the 2026 fold at h=66 and h=126, under the partial-year rule |
| `model` | Model name (see [Model names](#model-names)) |
| `n_test` | Number of test observations |
| `n_train` | Number of training rows after the embargo and NaN cleanup |
| `n_train_effective` | Effective independent observations, training rows / h. Because targets come from overlapping h-day windows, this is the real sample size |
| `rmse`, `mae` | The main metrics, in units of the daily log-return standard deviation |
| `r2_oos` | Secondary metric. Out-of-sample R² against the **training** target mean, a quantity known at forecast time. Exactly 0 for the train-mean baseline by definition |
| `r2` | Footnote metric. Standard R² against the test slice's **own** mean, an ex-post quantity. Frequently negative in calm years; not a basis for decisions |
| `Date` | Date as text, `DD.MM.YYYY` |
| `Date_parsed` | The same date as an ISO timestamp |
| `y_true` | Realized forward volatility, the target |
| `pred_<model>` | That model's prediction, in raw volatility units |
| `train_mean_target` | Mean of the training target, the train-mean baseline and the R²_oos reference |
| `runtime_seconds` | Wall-clock runtime of the script (JSON reports only) |

Aggregate files add:

| Column | Meaning |
| --- | --- |
| `n_folds` | Number of folds entering the average |
| `rmse_fold_mean`, `mae_fold_mean` | Fold average, the headline metric |
| `r2_oos_fold_mean`, `r2_fold_mean` | Fold average of R²_oos and of standard R² |
| `rmse_pooled`, `mae_pooled`, `r2_pooled`, `n_pooled` | Pooled over all test observations rather than averaged across folds. The pooled value runs systematically higher than the fold average because it also contains between-year variance |

## Stage 0: data validation

### `validate_data_report.json` — `validate_data.py`
Integrity report for the raw dataset: column and row checks, date monotonicity, NaN
counts, the largest calendar gap, and valid targets per horizon. The field
`ovx_record_check` verifies the OVX all-time record of 325.15 on 2020-04-21; if a rebuilt
dataset does not reproduce it, the wrong ticker was downloaded.

### `date_gaps_over_10_days.csv` — `validate_data.py`
Trading-day gaps longer than 10 calendar days. One row: the 17-day gap of April 2009.

| Column | Meaning |
| --- | --- |
| `gap_start`, `gap_end` | Dates bracketing the gap |
| `gap_days` | Gap length in calendar days |

### `horizon_valid_counts.csv` — `validate_data.py`

| Column | Meaning |
| --- | --- |
| `ufuk` | Horizon label (`1 hafta` = 1 week, `1 ay` = 1 month, `3 ay` = 3 months, `6 ay` = 6 months) |
| `h` | Horizon in trading days |
| `toplam_satir` | Total rows (4641) |
| `gecerli_hedef_sayisi` | Number of valid targets |
| `hedefsiz_son_satir` | Trailing rows with no target (equals h) |

### `horizon_valid_by_year.csv` — `validate_data.py`
Valid observations per calendar year, one column per horizon.

| Column | Meaning |
| --- | --- |
| `yil` | Calendar year |
| `1 hafta`, `1 ay`, `3 ay`, `6 ay` | Valid observations at h=5, 22, 66, 126 |

## Stage 1-2: targets and features

### `targets.csv` — `01_build_targets.py`
The four target columns, one row per date, NaNs preserved.

| Column | Meaning |
| --- | --- |
| `target_vol_5`, `target_vol_22`, `target_vol_66`, `target_vol_126` | Standard deviation of the next h days of daily log returns, computed with `skipna=False` |

### `build_targets_report.json` — `01_build_targets.py`
Valid-target counts per horizon against their expected values, plus the distribution
(min, median, max, count of negative values, which must be 0).

### `features.csv` — `02_build_features.py`
The causal feature matrix: 4641 rows, 65 features plus two date columns. Every feature is
shifted into the past; no fit() is involved. Feature name conventions:

| Pattern | Meaning |
| --- | --- |
| `<series>_lag1` … `_lag5` | Value lagged 1-5 days. `<series>` is `brent`, `ovx`, `gprd` or `gprd_threat` |
| `<series>_ema5/10/20` | Exponential moving average, shifted one day |
| `brent_ret_lag1` … `_lag5` | Lagged daily log return |
| `brent_vol5/20/60/126` | Realized volatility over that rolling window |
| `vol_ratio`, `vol5_vol60`, `vol20_vol126` | Short-to-long volatility window ratios, the volatility term structure |
| `ovx_z60`, `gprd_z60`, `gprd_threat_z60` | 60-day rolling z-score |
| `ovx_spike`, `gprd_spike`, `gprd_threat_spike` | Flag for z-score > 2 |
| `ovx_regime_high`, `ovx_regime_low` | Flag for OVX z-score above +1 or below −1 |
| `ovx_mr60` | Mean reversion, percentage deviation from the 60-day average |
| `gprd_momentum`, `gprd_threat_momentum` | EMA5 − EMA20 |
| `threat_ratio` | GPRD_THREAT / GPRD |
| `ovx_x_gprd`, `ovx_x_gprd_threat`, `ovx_regime_high_x_gprd`, `ovx_regime_low_x_gprd` | Interaction terms |
| `dow`, `month`, `is_month_start`, `is_month_end`, `is_quarter_end` | Calendar features, deliberately not shifted |

### `build_features_report.json` — `02_build_features.py`
Feature inventory with each feature's first valid row, plus the prefix-invariance test
result (the causality proof), infinite-value and constant-column scans, and the
diagnostic high-correlation pair lists. The field `high_corr_note` records that the
full-sample list must not be used for feature selection, because doing so would leak
test-period information.

## Stage 3: XGBoost, primary specification

Produced by `03_walkforward.py`. The `wf_*_h5/h22/h66/h126` files are per-horizon slices
of the corresponding `_all` file.

### `wf_predictions_all.csv`, `wf_predictions_h*.csv`
One row per test observation, with the XGBoost prediction and the two naive baselines.

### `wf_metrics_all.csv`, `wf_metrics_h*.csv`
Per-fold, per-model metrics.

| Column | Meaning |
| --- | --- |
| `sst_own` | Total sum of squares of the test slice around its own mean. This is the denominator of standard R², recorded to show how much it varies between folds (it reached a 53.6-fold range at h=5, which is why standard R² goes strongly negative in calm years) |

### `wf_aggregate_all.csv`
Fold averages and pooled values per horizon and model.

### `wf_summary_all.json`, `wf_summary_h5.json`
Full run record: configuration, the metric policy, the effective sample size table, the
2026 exclusion footnote, and `smearing_weak_folds`, the list of folds whose Duan smearing
factor fell below 1.02, which flags that the in-sample correction was too weak there.

## Stage 4: Optuna robustness analysis

Produced by `04_optuna_walkforward.py`. The `opt_rawsmearing_*` files are the
**pre-shrinkage** run, kept as a methodological example for the paper's appendix.

### `opt_folds_all.csv`, `opt_rawsmearing_folds_all.csv`

| Column | Meaning |
| --- | --- |
| `n_val_years` | Number of years in the validation window |
| `val_years` | Which years those are, comma-separated |
| `n_train_proper`, `n_val` | Rows in train-proper and in validation |
| `tp_effective`, `val_effective` | Effective independent observations for each |
| `capacity_tier` | Capacity tier used (see [Categorical values](#categorical-values)) |
| `optuna_used` | Whether a search actually ran in this fold |
| `n_trials` | Number of Optuna trials (30 when a search ran, 0 otherwise) |
| `selection_procedure` | Which procedure produced the hyperparameters |
| `best_params` | The selected hyperparameters |
| `val_rmse` | Validation RMSE of the selected configuration |
| `trial_val_rmse_best`, `trial_val_rmse_median`, `trial_val_rmse_worst` | Best, median and worst validation RMSE across trials |
| `selection_signal_pct` | How much better the best trial is than the median, in percent. **The key diagnostic**: below 5% the selection is most likely noise, which is the stated justification for preferring the fixed capacity rule |
| `smearing_raw` | Duan smearing factor before shrinkage |
| `smearing` | The factor after shrinkage, the one actually applied |
| `smearing_shrink_w` | The shrinkage weight w = n_eff / (n_eff + 10) |
| `smearing_n_eff` | Effective observations used for the shrinkage |
| `smearing_source` | Which residuals the factor came from |
| `refit_on` | Which data the final model was refit on |
| `sap_ham` | Absolute deviation of the raw factor from 1, \|smearing_raw − 1\| |
| `sap_buz` | Absolute deviation of the shrunk factor from 1, \|smearing − 1\| |

### `opt_metrics_all.csv`, `opt_rawsmearing_metrics_all.csv`
Per-fold metrics, carrying `selection_procedure` so the two procedures can be separated.

### `opt_aggregate_all.csv`, `opt_rawsmearing_aggregate_all.csv`

| Column | Meaning |
| --- | --- |
| `grup` | Which subset of folds the row aggregates: all of them, or only those from one selection procedure |

### `opt_predictions_all.csv`
Test predictions, with `selection_procedure` per row.

### `opt_summary_all.json`, `opt_rawsmearing_summary_all.json`
The validation rule, eligibility thresholds, search spaces, capacity tiers, the smearing
policy and its caveat, the refit policy, and `gains`, the comparison against the primary
specification.

### `opt_run_log.txt`
Console transcript, in Turkish. It includes the per-fold selection-signal warnings, which
are the evidence behind preferring the fixed capacity rule.

## Stage 5: econometric benchmarks

Produced by `05_benchmarks.py`. The `_aligned` variants restrict every model to XGBoost's

### `bench_metrics_all.csv`, `bench_aggregate_all.csv`, `bench_model_comparison_all.csv`

## Stage 6: Attention BiLSTM

Produced by `06_attention_bilstm.py`. The `_conv` variants come from the
`--convergence-mode` robustness check, which trains high-tier folds to a pre-declared
convergence criterion instead of a fixed epoch count.

### `bilstm_predictions_all.csv`, `bilstm_metrics_all.csv`, `bilstm_aggregate_all.csv`
Predictions, per-fold metrics and aggregates.

### `bilstm_folds_all.csv`, `bilstm_folds_all_conv.csv`

| Column | Meaning |
| --- | --- |
| `arch_tier` | Architecture tier, chosen from effective observations |
| `arch_hidden`, `arch_layers`, `arch_dropout`, `arch_weight_decay`, `arch_epochs` | The tier's architecture and regularization settings |
| `adaptive` | Whether this fold used convergence-criterion training (`_conv` files only) |
| `epochs_run` | Epochs actually run |
| `stop_reason` | Why training stopped (`_conv` files only) |
| `loss_start`, `loss_mid`, `loss_final` | Training loss at the first, middle and final epoch |
| `loss_p80` | Loss at the 80th-percentile epoch, the start of the final stretch |
| `tail_drop_pct` | Percentage decline in loss over the final 20% of epochs |
| `convergence` | Convergence classification derived from `tail_drop_pct` |

### `bilstm_summary_all.json`, `bilstm_summary_all_conv.json`

convergence thresholds and the degeneracy threshold.

### `all_models_comparison.csv`, `all_models_comparison_conv.csv`
The headline cross-model table: fold-average RMSE, MAE and R²_oos for every model at every
horizon. **This is the file behind the main finding.**

### `bilstm_run_log.txt`, `bilstm_conv_log.txt`
Console transcripts, in Turkish.

## Stage 8: Diebold-Mariano tests

Produced by `08_dm_test.py`. Loss is squared error; a negative DM statistic means the
first model is better.

### `dm_test_results.csv`

| Column | Meaning |
| --- | --- |
| `model1`, `model2` | The pair compared |
| `n` | Pooled observations |
| `lag` | HAC truncation lag, pre-declared as h − 1 |
| `rmse1`, `rmse2` | RMSE of each model |
| `rmse_orani` | Their ratio, rmse1 / rmse2. Below 1 means model1 is better |
| `fark_pct` | Percentage difference in RMSE. Negative means model1 is better. **Magnitude, as opposed to significance** |
| `d_ortalama` | Mean of the loss difference series |
| `DM_ham` | Raw DM statistic with the HAC correction |
| `p_ham` | Its standard-normal p-value |
| `DM_HLN` | DM statistic after the Harvey-Leybourne-Newbold small-sample correction. **The headline statistic** |
| `p_HLN` | Its p-value against t(n−1) |
| `hln_carpani` | The HLN correction multiplier |
| `DM_HACsiz` | DM statistic computed **without** the HAC correction |
| `p_HACsiz` | Its p-value, shown to expose how misleading the uncorrected test would be |
| `varyans_sisme` | Variance inflation factor, HAC variance divided by the variance under independence. The uncorrected test understates the standard error by its square root |
| `isaret_kazanan` | Sign-test winner: the number of folds in which model1 beat model2 |
| `isaret_fold` | Folds compared |
| `p_isaret` | Two-sided exact binomial p-value of that count. This test uses no HAC bandwidth, kernel or normality assumption |
| `aile` | Test family, confirmatory or exploratory |
| `p_HLN_holm`, `p_isaret_holm` | Holm-Bonferroni adjusted p-values, controlling the family-wise error rate, computed within each family |
| `p_HLN_bh`, `p_isaret_bh` | Benjamini-Hochberg adjusted p-values, controlling the false discovery rate, computed within each family |
| `anlamlilik` | Significance flag from the raw `p_HLN`: `***` below 0.01, `**` below 0.05, `*` below 0.10, empty otherwise |
| `dm_yon` | Which model the DM test favours |
| `isaret_yon` | Which model the sign test favours |
| `yon_uyumu` | Whether the two tests agree on direction. When they do, the finding is immune to the bandwidth choice |
| `ikisi_de_anlamli` | Whether both tests are significant at 5% |

### `dm_diagnostics.csv`
Autocorrelation diagnostic for the lag rule, on the HAR-X versus XGBoost pair.

| Column | Meaning |
| --- | --- |
| `cift` | The model pair, for example `har_x vs xgboost` |
| `acf_<k>` | Autocorrelation of the loss difference at lag k |
| `acf_ort_h_2h` | Mean autocorrelation between lags h and 2h. If this does not fall to zero, the HAC correction is still insufficient, which is expected for non-optimal forecasts |
| `varyans_sisme` | Variance inflation factor |

### `dm_summary.json`
The loss function, sign convention, HAC specification, the lag-rule caveat, the HLN
formula, the pooling assumption, the family definitions with their pre-registration
caveat, and the multiple-testing policy.

### `dm_run_log.txt`
Console transcript, in Turkish.

## Stage 9: statistical power analysis

Produced by `09_power_analysis.py`. Answers "could this difference have been detected with
this data?" as an order-of-magnitude estimate.

### `power_analysis.csv`

| Column | Meaning |
| --- | --- |
| `karsilastirma` | The comparison, as `model1 vs model2` |
| `rmse_fark_pct` | Percentage difference in RMSE |
| `dm_n_gunluk` | Daily observations available to the DM test |
| `dm_etkin_blok` | Effective independent blocks, n / h. This, not the row count, is the DM test's real sample size |
| `dm_istatistik` | Observed absolute DM statistic |
| `dm_p` | Its p-value |
| `dm_blok_basina_etki` | Standardized effect per block |
| `dm_gerceklesen_guc` | Achieved power. A monotone transform of the p-value that carries no new information, given for communication only |
| `dm_gerekli_blok` | Blocks required for 80% power |
| `dm_gerekli_gun` | The same requirement in daily rows |
| `dm_gerekli_yil` | The same requirement as test-period years. **The real answer** |
| `dm_kat_artis` | How many times larger the sample would have to be |
| `isaret_fold`, `isaret_kazanan` | Folds compared and folds won |
| `isaret_oran` | Observed win rate |
| `isaret_p` | Exact binomial p-value |
| `isaret_gerceklesen_guc` | Achieved power of the sign test |
| `isaret_gerekli_fold_yil` | Folds, and therefore years, required for 80% power |
| `isaret_kat_artis` | How many times more folds that would be |

### `apriori_power_sign.csv`
A priori power curves for the sign test, independent of the observed effects.

| Column | Meaning |
| --- | --- |
| `n_fold` | Number of folds |

## Stage 13: direct gap-target test

Produced by `13_gap_target_test.py`. Each real-gap return (see Stage 14) that spans 1 + k
trading days is rescaled to r / sqrt(1 + k), the target is rebuilt from the corrected
returns, and every model's committed predictions are re-scored against the corrected
target **with the predictions held fixed.** Only the evaluation target changes; no model
is refit. The number of changed test targets is asserted to equal `n_affected_test` in
`date_gap_target_exposure.csv` (recomputed with Stage 14's own functions), and the unmodified fold means are asserted to reproduce
`all_models_comparison.csv` and `ablation_exogenous.csv`.

## Stage 14: date-gap diagnostics

Produced by `14_date_gap_diagnostics.py`. The dataset is the inner join of four series, so
a return between consecutive rows can span more than one trading day. "Normal" non-trading
days are weekends and NYSE holidays (including the special closures of 2012, 2018 and
2025). England & Wales bank holidays are checked too: all 86 that fall on NYSE trading
days are present in the data, so the merged series follows the US calendar. A **real
gap** is a return whose span contains at least one weekday that is neither.

**Two different counts of affected targets.** A target is affected when its h-day window
contains a real-gap return. `*_full` counts every valid target from 2008 to 2026, the
2008-2011 warm-up included; `*_test` counts only the targets that enter the main
out-of-sample evaluation (test years 2012-2026, the 2026 fold excluded at h=66 and h=126).
The test count is the one that bears on the reported results, and the one
`13_gap_target_test.py` reproduces. At h=5 these are 198 of 4636 and 80 of 3662.
